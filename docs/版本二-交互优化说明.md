# 版本二：交互优化说明

页面最底部的「界面版本」可以在两个版本之间切换：

- **版本一 · 当前方案**：现有界面，默认版本，原样保留
- **版本二 · 交互优化**：围绕核心业务链优化流程，切到版本二后底部会出现「改动说明」，在页面里也能看到本文的方法和改动清单

两个版本读写同一份项目数据（`zhiying.projects.v1`），数据结构没有改动，可以随时切换对比。当前版本存在 `localStorage` 的 `zhiying.uiVersion` 里。

## 目标与约束

- 围绕核心业务链：立项 →（视频转写 → 拆解 → 引用）→ 故事架构 → 人物 → 大纲 → 伏笔 → 逐集写作 → 质检交付
- 不损失任何核心能力：版本一的每个功能、按钮、校验在版本二里都还在，不为删而删
- 不改数据结构，不改业务规则（环节准入、写作前检查、修稿上限、交付条件全部沿用）

## 方法：交互设计师怎么做流程优化

1. **画出任务链**：不按页面、按编剧要完成的事画：立项 →（视频转写 → 拆解 → 引用）→ 故事架构 → 人物 → 大纲 → 伏笔 → 逐集「集纲 → 蓝图 → 草稿 → 审稿 → 定稿」循环 → 质检交付。逐集循环要跑 60–80 遍，是全链路的主战场。
2. **走一遍，标断点**：以编剧身份把整条链走通，记下每一处「停下来想一想」的地方，归成五类：寻路（我在哪、还剩什么）、下一步（接下来做什么）、往返（为了一件事来回跳页）、反馈滞后（做完才知道不行）、一致性（同一件事在不同地方长得不一样）。
3. **对症用模式**：状态可见、任务导向的入口、随状态切换的主操作、前馈校验、就近操作与带上下文的往返。每个改动都要能指回一个断点，指不回的不做。
4. **守住约束**：不删功能、不改数据结构：版本一的每个按钮在版本二里都还在，只是排了先后、补了状态和去处。两个版本读写同一份项目数据，随时切换对比。

五类断点和对应的模式：

| 断点 | 编剧的疑问 | 常用模式 |
| --- | --- | --- |
| 寻路 | 我在哪？还剩什么？ | 状态可见：进度、状态图标、汇总清单 |
| 下一步 | 接下来做什么？ | 任务导向的入口、随状态切换的主操作 |
| 往返 | 为了一件事要来回跳几页？ | 就近操作、带上下文的跳转与返回 |
| 反馈滞后 | 为什么做完才告诉我不行？ | 前馈校验：边填边提示还差什么 |
| 一致性 | 同一件事为什么长得不一样？ | 统一的心智模型与组件 |

## 改动明细

### 1. 项目左侧 · 创作流程导航

- **版本一**：只有序号和环节名：看不出哪步做完、哪步卡住，也不知道为什么进不去。
- **版本二**：每个环节带状态图标（已完成 / 进行中 / 未开始 / 需先完成上游）和进度摘要（审核 2/4、集纲 12/60、定稿 3/60）；被拦住的环节悬停可见原因；顶部显示「n/N 环节完成」；导航做成白底面板，可收起成一列图标给正文腾地方，收起状态会记住。

### 2. 项目概览 · 继续工作

- **版本一**：「下一步」只到环节级（去逐集剧本），写作阶段停在草稿里的那一集要自己去草稿箱找。
- **版本二**：直接指到具体的事：停着的草稿优先（继续第 3 集草稿_v2：待审稿 → 按钮就是「AI 审稿」），其次是下一集，最后才是下一个环节。

### 3. 项目概览 · 待处理

- **版本一**：需要人工确认的事散在各环节：付费卡点集纲待审、伏笔逾期、伏笔推进待确认、质检严重问题、转写失败……要一个个点进去才知道。
- **版本二**：概览汇总成「待处理」清单，按严重程度排序，每条带直达按钮；和「继续工作」重复的那条不再出现。

### 4. 我的剧本 · 项目卡片

- **版本一**：卡片只有状态和集数，要点进项目才知道做到哪。
- **版本二**：卡片底部加环节进度条与「定稿 a/b 集」，以及「下一步 · …」按钮，一步回到上次的工作。

### 5. 各环节页头

- **版本一**：每次进入环节都展示同一段说明；环节做完后只有底部一行小字的「下一环节」。
- **版本二**：说明折叠为「环节说明」，需要时展开；本环节完成后页头出现「下一步」条，直接去下一个环节。

### 6. 对标剧拆解 · 四板块审核

- **版本一**：四个板块很长，要手动上下滚动逐个确认；审核进度条在最上方，往下审时就看不到了。
- **版本二**：审核条吸顶，点进度直接跳到对应板块；确认一个板块后自动滚到下一个没确认的，全部确认后落到「一键引用」。

### 7. 故事架构 · 确认

- **版本一**：点「确认故事架构」之后才列出缺了什么。
- **版本二**：状态卡吸顶并实时显示「确认前还差 N 项：…」，填完一项少一项；确认按钮照旧可点，逻辑不变。

### 8. 逐集剧本 · 单集流程

- **版本一**：一集的进度分散在分集蓝图列表、草稿箱、正文章节三处，要拼起来看。
- **版本二**：蓝图列表每集显示 5 个进度点，蓝图表单、草稿页统一显示「集纲 → 蓝图 → 草稿 → 审稿 → 定稿」步骤条；中间缺的步骤标「未做」，不冒充已完成；草稿写了还没审时停在「草稿」（还在改稿），审过才走到下一步，不提前点亮「审稿」；做过的步骤和写了一半的草稿可以直接点开（集纲 → 情节大纲里的这一集，草稿 / 审稿 → 最新草稿，定稿 → 正文），不用再回左侧草稿箱找。

### 9. 草稿页 · 主操作

- **版本一**：「AI 修稿 / AI 审稿 / 定稿」三个按钮同样醒目，编剧要自己判断先后。
- **版本二**：按审稿状态推荐下一步并说明原因（未审 → 审稿；审出严重问题 → 修稿；通过 → 定稿；按审稿改出的新版本提示再审一遍，确认意见都改到了），只有推荐的那个是主按钮，其余照旧可用。

### 10. 正文页 · 接力

- **版本一**：定稿后要回到分集蓝图页，选下一集再点「写作」。
- **版本二**：正文页顶部的接力条直接「写第 N+1 集」（照旧先过写作前检查），下一集已有草稿就直接打开；全部定稿后引导去质检交付。

### 11. 质检 → 正文 → 质检

- **版本一**：「去改正文」跳过去就丢了上下文：要自己找问题行，改完再找回质检和那条问题。
- **版本二**：跳转带上问题：正文页顶部显示问题与建议，问题行高亮并滚到眼前；「标记已处理并返回质检」一步回到原来那条问题。

### 12. 项目页头 · 保存

- **版本一**：数据自动保存在浏览器里，但界面上没有任何提示，编剧不确定改动是否还在。
- **版本二**：页头显示「已自动保存 · 时间」。

## 实现方式

- 版本开关：`src/store/uiVersion.ts`（`useV2()`），底部切换条与改动说明在 `src/v2/VersionBar.tsx`
- 版本二新增的组件与只读推导都在 `src/v2/`：`flow.ts` 从现有项目数据推导环节进度、下一步、待处理与单集步骤，不写入任何新字段
- 页面里的版本二分支都由 `useV2()` 控制，版本一除底部切换条外界面与行为不变；草稿写作逻辑抽到 `src/pages/workspace/script/write.ts`，蓝图页与正文页接力条共用
- 质检往返通过地址参数带上下文：正文页 `?from=qa&issue=<id>`，返回质检 `?issue=<id>`

## 验证

`node scripts/e2e.mjs <输出目录>` 先按版本一跑完原有检查，再切到版本二逐项验证：版本切换与改动说明、导航进度、继续工作与待处理、草稿页主操作切换与步骤条、正文页接力写下一集、质检带问题往返、环节页头、故事架构前馈提示、拆解审核条吸顶与自动滚动、项目卡片进度，最后切回版本一继续跑其余检查。截图以 `v2-` 开头。
