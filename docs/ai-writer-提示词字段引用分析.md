**结论先行**

ai-writer 的骨架是对的：作者写的设定是权威，每一步都带着上游，写正文时材料标来源，审稿硬查本章任务。没理顺的是三件事：

1. 顺序：架构四步前后说法不一致，人物和世界观互相读，配置层没有先后。
2. 分量：不分档，下游一律塞全文，AI 产物和作者原文同等对待。
3. 闭环：写、审、修各用一套依据，上游改了下游不知道。

第五部分给出合并后的整体逻辑：保留他们做对的，补上单向顺序、分档、按段取材、依据版本四样。

## 一、项目概况

### 1.1 是什么

ai-writer 是一个本地优先的长篇小说创作桌面应用（Electron + React + SQLite）。`AGENTS.md` 写明「ai-writer（代号 Vela）」，项目数据放在 `<项目根>/.vela/`，是我们之前分析过的 vela 的独立发行线。提示词骨架和 vela 相同，但架构步骤顺序、写正文的材料组织、审稿方式都有变化。

### 1.2 提示词怎么组织

| 部分 | 位置 | 作用 |
|---|---|---|
| 提示词清单 | `src/prompts/manifest.ts` | 每个提示词的 key、可用变量、必带字段（`requiredContextVariables`） |
| 提示词正文 | `src/prompts/zh-CN/*.md`、`en-US/*.md` | 分 name / description / systemRole / content / systemSuffix 几段 |
| 内部提示词 | `src/prompts/internal/` | JSON 合同、重试、人物两段式生成等，用户不能改 |
| 拼装 | `src/services/prompts/prompt-builder.ts` | 填变量；末尾追加 systemSuffix；必带字段兜底；残留占位符告警 |
| 调用方 | `src/services/workflows/commands/*.command.ts` | 每一步决定往变量里填什么 |

用户可以在设置页改大部分提示词（`EDITABLE_PROMPT_KEYS`），但 systemSuffix 永远取内置版本；用户删掉的必带字段，程序会在末尾补回。

### 1.3 数据分层

| 层 | 字段（界面名 / 代码名） | 谁写 |
|---|---|---|
| 小说配置 | 类型 `genre`、细分类型 `subGenre`、目标受众 `targetAudience`、总章数 `totalChapters`、每章字数 `wordsPerChapter`、故事结构 `plotStructure`、叙事视角 `narrativePOV`、核心大纲 `coreOutline`、世界观基盘 `worldSetting`、金手指 `goldenFinger`、主角人设 `protagonistProfile`、全局写作要求 `globalGuidance`、文风 `writingStyle`、参考作品 `referenceWorks` | 作者手填；或一句话灵感由 AI 一次生成；或单项 AI 补全 |
| 故事架构 | 故事前提 `premise`、角色图谱 `charactersArch`（另存结构化角色名单）、世界观 `worldbuilding`、情节大纲 `synopsis` | AI 生成，作者可改 |
| 章节蓝图 | 每章：章号、标题、定位 `role`、目的 `purpose`、出场人物、人物关系、关键事件 `keyEvents`、悬念钩子 `suspenseHook` | AI 分批生成 |
| 正文与事实 | 草稿、定稿、角色卡（含当前状态 `currentState`）、章节要点、叙事线索、审稿报告、知识库 | AI 写、作者改；定稿后自动抽取 |

> 「世界观基盘」在界面上叫「世界观设定」，提示词里叫「世界观基盘」。本文统一叫基盘，以便和故事架构里生成的「世界观」区分。

## 二、现状：每一步的字段引用

### 2.1 总览

代码默认的架构顺序是 前提 → 世界观 → 情节大纲 → 角色图谱（`architecture-workflow.ts:67`），下图按这个顺序画。顺序本身的问题见第四部分问题 1。

```
一句话灵感 ──▶ 小说配置（一次全出 / 单项补全）
                 │
                 ▼
  故事前提 ◀── 全部配置
     │
     ├──▶ 世界观 ◀── 基盘、金手指、主角人设、全局写作要求、类型；已有角色图谱（注释里叫“上游”）
     │
     ├──▶ 情节大纲 ◀── 前提 + 角色图谱 + 世界观 + 篇幅、结构模板、视角、全局写作要求
     │
     └──▶ 角色图谱 ◀── 前提、类型、主角人设、全局写作要求、参考作品
                 │
                 ▼
  章节蓝图 ◀── 前提 + 角色图谱 + 世界观 + 情节大纲（全文）+ 最近 100 章 + 全局写作要求 + 节奏指导
                 │
                 ▼
  写正文 ◀── 前提 + 世界观 + 情节大纲（全文）+ 配置原文 + 出场人物卡 + 本章蓝图
             + 后 5 章蓝图 + 定稿原文 + 叙事线索 + 知识库
                 │
                 ▼
  审稿（本章关键事件 + 连续性）──▶ 修稿（审稿意见 + 全局写作要求）──▶ 定稿
                 │
                 ▼
  定稿后抽取：角色状态、章节要点、叙事线索
```

| # | 步骤 | 提示词 key | 实际发给模型的内容 | 产出 | 代码位置 |
|---|---|---|---|---|---|
| 1 | 一句话生成配置 | `generate_global_config` | 灵感、总章数、每章字数 | 全部配置项，一次调用出完。交卷字段顺序：类型、受众、细分、结构、视角、核心大纲、世界观基盘、金手指、主角人设、全局写作要求、文风 | `generate-config.command.ts`；`generate_global_config.md:35` |
| 2 | 单项补全 | `generate_novel_config_field` | 已填的全部配置平铺，不分先后，包括本该排在它后面的项；再加该字段的写法要求 | 一项配置 | `generate-field.command.ts:219-243` |
| 3 | 故事前提 | `premise` | 全部配置：类型、细分、核心大纲、受众、篇幅、世界观基盘、金手指、主角人设、全局写作要求、参考作品；本步作者指导 | 一句话前提、核心冲突链、金手指定位、悬念骨架 | `generate-core-seed.command.ts:56-68` |

| 5 | 情节大纲 | `synopsis` | 故事前提、角色图谱、世界观（三者必须已存在）；类型、总章数、每章字数；结构模板（按 plotStructure 和总章数换算）；叙事视角、全局写作要求、本步作者指导 | 全书结构拐点，标章节区间；可分批、可断点续写 | `generate-plot-architecture.command.ts:76-90, 285-296` |
| 6 | 角色图谱 | `character_dynamics` + 内部两段式 | 实际只发 JSON：故事前提、类型、主角人设、全局写作要求、本步作者指导、参考作品；已有角色图谱放最前 | 先出身份清单（人数、关系），再分批补详情 | `generate-characters.command.ts:126-160` |
| 7 | 章节蓝图 | `chapter_blueprint_chunk` | 前提、角色图谱、世界观、情节大纲全文（各自超过 50 字才带）；前面已生成的最多 100 章「标题：关键事件」；类型、总章数、全局写作要求、节奏指导 | 每章结构化蓝图 | `directory-workflow.ts:210-221`；`directory.command.ts:487-502` |

| 9 | 精修 | `refine_chapter` | 草稿、本章信息、全局写作要求、近章摘要、篇幅、文风、作者指导 | 精修稿 | `manifest.ts` |
| 10 | 审稿 | 助手工具 `submit_chapter_review` | 助手自行取材写意见；程序再加两项硬核对：本章蓝图关键事件有没有逐条落实、和定稿内容的连续性预检 | summary + 1–10 条（error / warning / pass；error 和 warning 必须引原文） | `submit-chapter-review.tool.ts:150-152` |

补充说明：

- 第 6 步的 `character_dynamics.md` 正文没有发给模型。实际发的是内部提示词（身份清单 + 详情）加 JSON 上下文，`character_dynamics` 只贡献 systemRole 和用户自定义部分。模板里写的金手指、世界观、总章数，只在用户自定义提示词时才会代入；而且「世界观」代入的是世界观基盘（`generate-characters.command.ts:142-147`）。
- 一致性审稿模板 `consistency_check`（正文、角色状态、全局摘要、世界观）还在清单里，但这次拉下来的代码里没找到调用方。据此判断，审稿已改为走助手工具。

### 2.3 写正文的材料包

写正文是引用最多的一步。下表按内容在提示词里出现的位置排列：

| 区块 | 内容 | 标签 / 口吻 |
|---|---|---|
| 材料包（最前） | 核心大纲、世界观基盘、金手指、主角人设原文；本章出场人物的角色卡 | 「作者资料（保留原文；人物状态具有时点，不是永久约束）」 |
| | 后 5 章蓝图「第 N 章 标题：关键事件」 | 「后续计划边界（只约束当前章，不是当前章任务）」 |
| | 定稿原文片段（按相关度挑）、未定稿候选、活跃叙事线索、知识库检索 | 「定稿原文只证明原文直接写明的内容；索引、摘要和 currentState 都不是作者事实；候选不得冒充定稿」。超预算时可省略，并记录缺口 |
| 提示词正文 | 前提 + 世界观 + 情节大纲全文（`readArchitecture`，不含角色图谱） | 首章叫「全书设定池」；后续章放在 systemSuffix 的「不可偏离的作者事实」 |
| | 小说配置去掉 6 个长字段后的 JSON（类型、受众、篇幅、结构、视角等） | 「不可偏离的作者事实」 |
| | 本章蓝图 JSON；全局写作要求（加项目 prompts 目录下的 md）；文风 | 文风「只用于选择表达方式，不是新增事实」 |
| | 本步作者指导 | 「最高优先级」 |
| 末尾 | 本章执行卡：关键事件、钩子、作者指导原文重列 | 「不是新增事实，输出前核对已落实」 |
| | 篇幅合同：目标字数 ±20% | 「不得为篇幅删改必需事件」 |

位置：`generate-draft.command.ts:128-360, 817-824`；`chapter-materials.ts:139-232`。

### 2.4 提示词里的约束口吻

全套提示词只有下面这几种口吻，没有分档：

1. 作者事实：「作者明确设定是权威事实，不得遗漏、弱化、反转或用题材惯例替换」。所有架构步骤、蓝图、正文都用。
2. 最高优先级：每个提示词都有一段「★作者对本步骤的额外指导（如有，最高优先级）★」；蓝图里是「作者节奏/风格指导（最高优先级）」。
3. 边界：后几章蓝图、上一章结尾「只作边界，不可重演 / 不可提前」。
4. 来源：定稿原文、候选、摘要分开标。
5. 文风边界：只管表达，不新增事实。
6. 题材常识写死在提示词里：蓝图的「黄金三章」「3–5 章一个小高潮」「伏笔强制回收」。

## 三、和我们 11/2 讨论的区别

对照 `问题讨论-故事架构与生成依据.md`：

| 方面 | ai-writer | 我们的讨论 | 对应问题 |
|---|---|---|---|
| 源头 | 小说配置（作者层）是源头，故事架构是 AI 展开 | 核心设定是源头；七项设定 + 基本信息是指挥棒 | 1 |
| 分量 | 不分档；传进去的作者设定一律「权威」，上游全部给全文 | 三档：必须遵守 / 重点参考 / 不违背即可。档位决定给全文还是摘要、审稿算严重还是建议 | 2 |
| 原创怎么推 | 一句话灵感一次出全部配置，项与项没规定先后；单项补全平铺读全部 | 先拆核心设定（原文 / 推断 / 补充），按五层顺序逐项推，每项只读前面的 | 3、4 |
| 架构顺序 | 代码：前提 → 世界观 → 情节 → 人物；提示词和注释：前提 → 人物 → 世界观 → 情节 | 起点 → 人与卖点 → 世界 → 结构 → 写法；先人后世界 | 5 |
| 创新点 | 没有这个字段 | 原创在结构层；仿写紧跟改写方案 | 6 |
| 中间层 | 情节大纲 → 直接逐章蓝图 | 全剧总览 → 阶段粗纲 → 集纲 → 分集蓝图 | 3.4 |
| 下游取材 | 蓝图、正文都塞全部架构全文 | 按粒度取：粗纲读冲突主线的这一段，集纲读所在阶段 | 3.4 |
| 伏笔 | 定稿后抽叙事线索，写后续章节时带上；没有事前计划 | 情节大纲后做伏笔计划，集纲、蓝图、写作都读 | 3.4 |
| 写正文 | 前提、世界观、情节大纲全文都标不可偏离 | 必须遵守只放全局写作要求、人物设定、本集集纲、分集蓝图、状态库 | 3.4 |
| 审稿 | 查本章关键事件落实 + 连续性；严重程度由模型判断 | 每条带依据（8 类），有依据才可能严重；新增「偏离核心设定」 | 9；审稿收敛 |
| 修稿 | 只读审稿意见 + 全局写作要求 | 写作、审稿、修稿用同一份依据 | 审稿收敛 |
| 上游改了 | 只有情节大纲有依据指纹（用于断点续写） | 标「依据已改」，不自动重写（待定） | 12 |
| 冲突听谁的 | 没规定；「作者事实不可偏离」和「作者指导最高优先级」并列 | 事实类听上游，情节安排类听更具体的（待定） | 13 |
| 仿写 | 没有；「导入」是旧作逆向推演后接着写 | 对标剧拆解 → 改写方案 → 创新点 → 逐项对位 | 6、7、8 |
| 短剧字段 | 没有节奏框架、爽点公式、付费卡点、主要势力、故事背景 | 都有 | — |

## 四、没理顺的地方

每条按现象、证据、影响写。

### 问题 1：架构四步的顺序前后说法不一致

- **现象**：代码默认顺序是 前提 → 世界观 → 情节大纲 → 角色图谱，另外几处都认为人物在世界观前面。
- **证据**：
  - 默认顺序：`architecture-workflow.ts:67`，步骤定义也按这个顺序排（`:94-129`）。
  - 情节大纲要求角色图谱已存在，否则报「角色图谱未生成」：`generate-plot-architecture.command.ts:85`。
  - 世界观的代码注释：「上游角色图谱 + 本块已有世界观，都作为作者权威参考」：`generate-world-building.command.ts:75`。
  - 提示词描述：前提「故事架构第一步」，角色图谱「第二步」，世界观「第三步」。
  - 旧版 vela 的顺序是 前提 → 人物 → 世界观 → 情节（见 `vela-分析报告.md`）。
- **影响**：
  - 照代码看，新项目一次跑完会在情节大纲这一步报错（界面有没有绕开没看到）。
  - 就算分开跑，世界观先于人物生成时也读不到「上游」角色图谱，注释里的设计意图落空。

### 问题 2：人物和世界观互相读，同一个变量名指两样东西

- **现象**：
  - 世界观读已生成的角色图谱，人物读世界观基盘，形成循环。
  - `world_building` 这个变量在情节大纲里是生成的世界观，在人物这一步却是配置里的基盘。
- **证据**：`generate-world-building.command.ts:76-78`；`generate-characters.command.ts:144`；`generate-plot-architecture.command.ts:288`。
- **影响**：
  - 两步都重新生成时，结果取决于谁先跑。
  - 改提示词的用户看到 `{{world_building}}`，会以为拿到的是生成的世界观。

### 问题 3：模板里写的和实际发的不一致

- **现象**：
  - 角色图谱模板写了「金手指使用风格（基于 {{golden_finger}}）」、世界观背景、预期篇幅。这些只在用户自定义提示词时代入，默认不发。
  - 精修模板要求「将金手指的使用细节融入战斗或博弈」「强化反派的压迫感」，但精修的变量里既没有金手指，也没有人物资料。
- **证据**：`generate-characters.command.ts:126-147`；`refine_chapter.md:25-26`，以及 `manifest.ts` 里 `refine_chapter` 的变量列表。
- **影响**：
  - 模型被要求用它没拿到的信息，只能自己编。
  - 读提示词的人以为这些信息带上了。
  - 程序只检查「占位符没填上」（`prompt-builder.ts:66`），不检查「写了要用却没传」。

### 问题 4：同一件事两份来源，冲突时不知道听谁的

- **现象**：
  - 核心大纲（配置）和故事前提（架构）：前提里又写了一节「金手指定位」，和配置的金手指重复。
  - 世界观基盘（配置）和世界观（架构）。
  - 主角人设（配置）和角色图谱里的主角。
- **证据**：
  - `premise.md:34`。
  - 写正文时，配置原文进「作者资料」（`generate-draft.command.ts:313`）；前提和世界观进「不可偏离的作者事实」（`next_chapter_draft.md:43-44`）。
- **影响**：AI 在前提里改写了金手指的机制或限制后，写正文时两个版本同时出现，而且都标成权威。

### 问题 5：AI 产物直接当作者事实

- **现象**：前提、世界观、情节大纲由 AI 生成，写正文时却整段标成「不可偏离的作者事实」。
- **证据**：`next_chapter_draft.md:43-44`；`readArchitecture`（`generate-draft.command.ts:817-824`）。没看到「作者确认过」之类的标记字段；工作流即使有逐步确认，确认也没有存成下游能读的标记。
- **影响**：
  - AI 编的细节和作者亲手写的东西一样硬，作者没细看过的段落也会把正文锁死。
  - 题材套路一旦写进前提，后面就绕不开了。

### 问题 6：「防止提前写」自相矛盾

- **现象**：后 5 章蓝图专门标了「只作边界，不是本章任务」；同一个提示词里，情节大纲全文（含中后期和结局）却标成不可偏离的事实。
- **证据**：`generate-draft.command.ts:154`、`chapter-materials.ts:221`；`readArchitecture` 带的是 `synopsis` 全文。
- **影响**：
  - 模型知道后 5 章不能写，却把整本书的走向当成「必须遵守」，提前铺垫甚至提前兑现远期情节的风险最高。
  - 长篇的情节大纲很长，每章都带也浪费预算。

### 问题 7：优先级没有次序

- **现象**：
  - 每个提示词都同时有「作者事实不可偏离」和「作者指导最高优先级」。
  - 蓝图里还有「作者节奏指导最高优先级」，外加写死的「黄金三章」「3–5 章一个小高潮」。
- **证据**：10 个提示词都有「最高优先级」段（如 `next_chapter_draft.md:52`、`chapter_blueprint_chunk.md:41`）；`chapter_blueprint.md:25-26`、`chapter_blueprint_chunk.md:31`。
- **影响**：
  - 作者指导说「这章主角输」、前提写着「主角每次都赢」时，模型取哪个说不准。
  - 作者想写慢热，题材节奏规则照样生效。

### 问题 8：下游取材不分粒度，伏笔没有事前计划

- **现象**：
  - 每一批蓝图都带全部架构全文，再加最近 100 章「标题：关键事件」，不按「这一批属于情节大纲的哪一段」取。
  - 蓝图要求「伏笔强制回收：前面留下的危机必须引爆或解决」，但前文只有标题和关键事件，没有伏笔字段。
  - 伏笔只在定稿后抽取（叙事线索、章节要点），写之前没有计划。
- **证据**：`directory-workflow.ts:211-214`；`directory.command.ts:487`；`chapter_blueprint_chunk.md:32`。
- **影响**：
  - 长篇写到后期，每一批的提示词越来越长，本段该做的事被稀释。
  - 伏笔该不该收、收哪条，全靠模型从关键事件里猜。

### 问题 9：写、审、修三套依据

- **现象**：
  - 写正文读得最全。
  - 审稿只硬查本章关键事件和连续性，不查设定违反。
  - 按审稿修稿只读审稿意见和全局写作要求。
- **证据**：`submit-chapter-review.tool.ts:150-152`；`refine-from-review.command.ts:216-221`。
- **影响**：
  - 正文违反金手指限制、世界规则时，审稿不一定发现得了。
  - 修稿看不到设定，修一处可能改出新的矛盾。

### 问题 10：上游改了，只有一处知道

- **现象**：只有情节大纲记了依据指纹（前提、角色、世界观、篇幅、结构、视角、全局写作要求），这些一变就拒绝断点续写。其余产物都没记。
- **证据**：`generate-plot-architecture.command.ts:174-183, 279`。
- **影响**：作者改了金手指或主角人设后，已有的前提、蓝图、正文没有任何提示，下游继续按旧设定写。

### 问题 11：配置层没有先后

- **现象**：
  - 一句话生成时，一次出完全部配置。
  - 单项补全时，平铺读全部已填项，包括本该排在它后面的项。
- **证据**：`generate_global_config.md:35`；`generate-field.command.ts:219-243`。
- **影响**：
  - 先写主角人设再补金手指，和先补金手指再写主角人设，得到的依据完全不同。
  - 作者看不出某一项是根据哪几项推出来的。

## 五、整体逻辑建议

### 5.1 原则

保留他们做对的四条，再补上我们讨论里的四条：

| 来源 | 原则 |
|---|---|
| 沿用 | 作者写的是权威，AI 只能展开，不能改写 |
| 沿用 | 材料标来源：作者原文、定稿事实、未定稿候选、摘要分开 |
| 沿用 | 只给本步需要的边界：上一章结尾、后几章计划只作边界 |
| 沿用 | 本章任务写成清单，写完逐条核对 |
| 补充 | 单向顺序：每一项只读排在它前面的项 |
| 补充 | 分档：每个依据标必须遵守 / 重点参考 / 不违背即可 |
| 补充 | 按粒度取材：越往下，越只读「这一段」 |
| 补充 | 闭环：写、审、修用同一份依据；上游改了，下游知道 |

### 5.2 流程

```
作者输入（一句话灵感 / 已手填的项）
  ↓
① 小说配置（作者层）
   基本信息 → 核心大纲 → 金手指 → 主角人设 → 世界观基盘 → 全局写作要求 → 文风
   （参考作品由作者手填）
  ↓
② 故事架构（AI 展开；作者确认后才算事实）
   故事前提 → 角色图谱 → 世界观 → 情节大纲（分段，每段带章节区间）
  ↓
③ 伏笔计划（新增：每条埋在哪段、收在哪段）
  ↓
④ 章节蓝图（按段分批）
  ↓
⑤ 写正文 → ⑥ 审稿 → ⑦ 修稿 / 精修 → ⑧ 定稿
  ↓
⑨ 定稿后抽取：角色状态、章节要点、叙事线索
   （已发生的事实，回流给 ④⑤⑥；叙事线索和 ③ 对账）
```

和现在的差别：

| 环节 | 改动 |
|---|---|
| ① 小说配置 | 规定先后。一次生成也按这个顺序出；单项补全只把排在前面的项当依据 |
| ② 故事架构 | 只改代码里的默认顺序，就和他们自己的提示词、注释、前置检查对齐了。人物读基盘（作者写的），世界观读角色图谱（生成的），只有一个方向 |
| 情节大纲 | 分段存，下游按段取 |
| ③ 伏笔计划 | 新增 |
| ⑦ 修稿 / 精修 | 读和写正文同一份「必须遵守」 |

为什么人物排在世界观前面：

- 核心大纲里信息最多的是主角和金手指，先把人定下来。世界观是为了让人和能力成立而补的规则，这样补的比例小，也不容易套模板。
- 世界观里的阶层和阵营，要先知道主要角色站在哪边。
- 和他们提示词的标号、代码注释、旧版 vela 一致，改动最小。

### 5.3 四条总规则

#### 规则 1：权威次序

| 次序 | 来源 | 在提示词里怎么标 |
|---|---|---|
| 1 | 作者手写或手改过的内容 | 作者原文 |
| 2 | 定稿正文里写明的事实 | 定稿事实 |
| 3 | 作者确认过的 AI 产物 | 已确认设定 |
| 4 | 未确认的 AI 产物 | 参考，不能标「作者事实」 |
| 5 | 题材常识（黄金三章、3–5 章一个小高潮等） | 只补空 |

同一级里，再按事实类和情节安排类分开：

| 类型 | 包括 | 冲突时 |
|---|---|---|
| 事实类 | 世界规则；金手指能做什么、不能做什么；人物身份和关系；全局写作要求里的禁止项 | 上游说了算，下游写反就是错 |
| 情节安排类 | 这一章、这一段发生什么 | 越具体的越说了算：本章蓝图 > 本段大纲 > 故事前提。偏离太远要提醒 |

「最高优先级」的用法：

- 只留给本步作者指导，管本步的情节安排和题材常识，不能推翻事实类设定。
- 真冲突时照指导写，同时在结果里提示「与设定 X 冲突」，由作者决定改设定还是改指导。
- 蓝图的节奏指导并入本步作者指导，不再单独占一个「最高优先级」。

#### 规则 2：分三档

| 档 | 给什么 | 提示词里标 | 审稿查出来算 | 超出长度预算时 |
|---|---|---|---|---|
| 必须遵守 | 全文 | 不可偏离 | 硬伤 error | 不裁 |
| 重点参考 | 全文或本段 | 参考，结果里要看得出来 | 建议改进 warning | 其次裁 |
| 不违背即可 | 一两句摘要 | 不得写反 | 建议改进 warning | 最先裁 |

落地方式：

- 提示词清单现在只有「必带字段」一个列表，改成给每个变量标档位。
- 拼装时按档位决定给全文还是摘要、加哪个标签、超预算先裁谁。
- 写正文的材料包已经有「超预算省略可选材料并记录缺口」（`chapter-materials.ts:139-142`），按档位来裁就行。

#### 规则 3：依据版本

- 每份产物（前提、角色图谱、世界观、情节大纲、蓝图、正文）都记下生成时用到的依据指纹，做法照搬情节大纲的 `synopsisInputsFingerprint`。
- 上游一改，下游标「依据已改」，并列出改的是哪一项。
- 不自动重写。由作者决定重新生成、手改，还是忽略。

#### 规则 4：提示词就是契约

- 一个变量名只指一个字段：世界观基盘统一叫 `core_setting`，只有生成的世界观才叫 `world_building`。
- 模板里出现的变量必须真的传值。现在只检查「占位符残留」，还要加反向检查：清单里登记了、模板里用了，却没传值。
- 内置模板正文要和实际发出的内容一致。像角色图谱这种两段式生成，要么把模板正文真正用起来，要么在设置页说明这个模板只影响哪部分。

### 5.4 小说配置层：顺序和依据

| 顺序 | 配置项 | 必须遵守 | 重点参考 | 不违背即可 |
|---|---|---|---|---|
| 0 | 基本信息（类型、细分、受众、篇幅、结构、视角） | 作者已填的项 | 一句话灵感 | — |
| 1 | 核心大纲 | 一句话灵感（或作者草稿） | 类型、细分、受众 | 篇幅 |
| 2 | 金手指 | 核心大纲里的能力 / 反常规点 | 类型、细分 | 受众、篇幅 |
| 3 | 主角人设 | 核心大纲里主角的身份和困境 | 金手指（性格怎么配能力）、受众 | 叙事视角 |
| 4 | 世界观基盘 | 核心大纲里的时代、地点、身份 | 类型、细分；金手指（规则怎么容纳它） | 主角人设 |
| 5 | 全局写作要求 | 叙事视角、每章字数 | 类型、受众；世界观基盘里的硬规则（写成禁止项） | 核心大纲（保留他们「不许复述大纲」的规则） |
| 6 | 文风 | — | 类型、受众、参考作品 | 全局写作要求 |
| — | 参考作品 | 作者手填，AI 不生成 | — | — |

- **一句话生成**：仍可以一次调用，但交卷字段要按这个顺序排（现在世界观基盘排在金手指、主角人设前面），并在提示词里写明「后项以前项为准」。
- **单项补全**：排在它前面的项和作者手写的项进「必须遵守」，排在后面的项进「不违背即可」。
- **核心大纲没写时**：从灵感里拆。原文写明的直接用；能推断的标「推断」；完全没有的用题材常识补，标「补充」。作者确认时重点看「补充」。

### 5.5 故事架构层：每一步的依据

| 步骤 | 必须遵守 | 重点参考 | 不违背即可 | 和现在比 |
|---|---|---|---|---|
| 故事前提 | 核心大纲、金手指、主角人设、世界观基盘（作者原文） | 类型、细分、受众、篇幅、参考作品 | 全局写作要求 | 前提只展开核心大纲。「金手指定位」改成引用配置原文，只补它和世界规则怎么互动、怎么进阶，不重写机制和限制 |
| 角色图谱 | 主角人设、故事前提 | 金手指（主角怎么用）、世界观基盘（身份职业要成立）、总章数（定人数）、类型、受众 | 全局写作要求、参考作品 | 把模板里写了、却没发的金手指、基盘、总章数真正发出去 |
| 世界观 | 世界观基盘、故事前提 | 金手指（规则怎么容纳它）、角色图谱（阶层、阵营站位） | 主角人设、全局写作要求 | 继续读角色图谱；顺序调整后不再循环 |
| 情节大纲 | 故事前提、总章数、结构模板 | 角色图谱（弧光）、世界观（深层危机何时揭开）、金手指（进阶节点）、叙事视角 | 全局写作要求 | 输出改为分段（见 5.6） |

每一步产出后附一段依据说明：用了哪几项，哪些内容是展开、哪些是补充。作者确认后，这一步标为「已确认」，对应规则 1 的第 3 级。

### 5.6 情节大纲分段格式

他们现在已经要求结构节点带章节区间，只要再改成结构化存储：

| 字段 | 说明 |
|---|---|
| 段名 | 如「开局受辱」「第一次翻盘」 |
| 章节区间 | 第 a–b 章；各段加起来等于总章数 |
| 本段事件 | 这一段要发生的几件事 |
| 本段揭开 | 世界观或人物的秘密，在这一段揭开哪些 |
| 金手指节点 | 本段的获得、升级、代价 |
| 高潮位置 | 本段的小高潮、大高潮落在哪几章 |
| 一行摘要 | 给其他段当「不违背即可」时用 |

断点续写和依据指纹照旧。

### 5.7 伏笔计划（新增）

| 字段 | 说明 |
|---|---|
| 线索名 | 如「玉佩来历」 |
| 埋设 | 第几段 / 第几章 |
| 回收 | 第几段 / 第几章 |
| 涉及人物 | 角色图谱里的人 |
| 来源 | 世界观秘密、人物秘密、金手指来历或代价 |
| 状态 | 计划 / 已埋 / 已收 / 废弃 |

- **生成依据**：
  - 必须遵守：情节大纲各段。
  - 重点参考：世界观里的隐藏真相、角色秘密、金手指的来历和代价。
  - 不违背即可：故事前提。
- **下游怎么用**：
  - 生成蓝图时，读本批章节区间内要埋、要收的条目。
  - 定稿后抽出的叙事线索，按线索名回填状态。
  - 到了回收章还没收的，审稿时提示。

### 5.8 下游：每一步的依据

| 步骤 | 必须遵守 | 重点参考 | 不违背即可 | 和现在比 |
|---|---|---|---|---|
| 章节蓝图（按段分批） | 本段大纲、上一章蓝图（承接）、总章数 | 本段伏笔计划；涉及人物的角色卡；最近若干章「标题：关键事件」；本步作者指导（含节奏） | 世界观规则摘要、金手指限制、其余各段一行摘要、全局写作要求、题材节奏常识 | 不再每批塞全部架构全文；黄金三章等降为常识，只补空；蓝图增加「本章埋 / 收的伏笔」字段 |
| 写正文 | 本章蓝图和执行卡；上一章结尾；相关定稿事实；出场人物角色卡；配置里的事实类设定（金手指限制、世界规则、禁止项）；全局写作要求；篇幅合同 | 本段大纲、本章伏笔计划、活跃叙事线索、文风 | 故事前提摘要、世界观摘要、后几章蓝图（边界） | 情节大纲全文换成本段（解决问题 6）；未确认的 AI 产物不再标「作者事实」 |
| 审稿 | 和写正文同一份 | 同左 | 同左 | 保留引原文、硬查关键事件、连续性预检。新增：按依据查设定违反、到期伏笔没收、偏离故事前提；每条写明依据名，档位决定严重程度 |
| 按审稿修稿 | 人工确认的审稿意见；写正文的必须遵守档 | — | — | 现在只读全局写作要求 |
| 精修 | 草稿、本章蓝图、出场人物角色卡、金手指、全局写作要求 | 文风 | 本段大纲摘要 | 补上模板要求用、却没给的金手指和人物 |
| 定稿后抽取 | — | — | — | 保留；新增叙事线索和伏笔计划对账，并回写状态 |

### 5.9 写正文提示词的排列

他们按「稳定前缀 → 可变后缀」排列，为的是命中上下文缓存，这一点保留。在此基础上按档位分区：

```
【稳定前缀，跨章不变】
1. 必须遵守 · 设定：配置里的事实类设定、全局写作要求、文风边界
2. 不违背即可 · 摘要：故事前提摘要、世界观摘要
【随段变化】
3. 重点参考 · 本段：本段大纲、本段伏笔计划
【随章变化】
4. 必须遵守 · 事实：上一章结尾（边界）、相关定稿原文、出场人物角色卡
5. 重点参考：活跃叙事线索、知识库检索
6. 不违背即可：后几章蓝图（边界）
7. 本章任务：本章蓝图
【末尾】
8. 本步作者指导（范围见规则 1）
9. 本章执行卡 + 篇幅合同
```

### 5.10 审稿依据和严重程度

| 依据 | 档 | 违反算 |
|---|---|---|
| 本章蓝图关键事件没落实 | 必须遵守 | 硬伤 |
| 和定稿事实、上一章结尾矛盾 | 必须遵守 | 硬伤 |
| 违反金手指限制、世界规则、禁止项 | 必须遵守 | 硬伤 |
| 人物身份、关系、能力和角色卡不符 | 必须遵守 | 硬伤 |
| 篇幅超出 ±20% | 必须遵守 | 硬伤 |

| 偏离故事前提；写了后几章的事 | 不违背即可 | 建议改进（明显写反的可升为硬伤） |
| 没有依据的意见 | — | 只能是建议，不能是硬伤 |
