# 剧本 Agent

面向出海短剧的 AI 剧本创作工作台 Demo：从立项、对标剧拆解、故事架构，到逐集剧本与质检交付，把编剧流程拆成可逐步确认的环节。

> 阶段 1–3（立项、剧本仿写 + 解析、视频转剧本）与质检交付均已上线。AI 能力使用本地模拟（`src/services/ai.ts` + `src/services/mock/`），接口形状与真实大模型调用一致，后续接入后端只需替换 provider。

## 功能

### 阶段 1：立项

- **工作台 / 我的剧本**：剧本卡片、状态（立项中 / 创作中 / 质检中 / 已交付）、搜索与筛选
- **新建剧本**：一整页填完点击创建，分为基本信息、故事设定、市场与发行三部分；故事设定从「核心设定」写起（可让 AI 给候选），单集时长按秒填写（30–300 秒），与总集数同一行；创作方式（原创剧本 / 对标剧仿写 / 视频转剧本）创建后不可更改
- **项目工作区**：概览（创作进度，项目状态在进度卡右上角点选即保存；故事架构卡、项目设定、动态）、项目设置（「返回」回到来源页，未保存修改离开前拦截）；概览页显示完整页头，进入各环节后页头收成一行（面包屑 + 小封面 + 剧名 + 状态），点剧名回概览；点击页头封面可更换封面配色
- 数据保存在浏览器 localStorage（`zhiying.projects.v1`，带版本迁移），无需后端

### 阶段 2：剧本仿写 + 解析

| 环节 | 内容 |
| --- | --- |
| 对标剧拆解 | 导入对标剧本 → AI 拆成故事梗概、人物、冲突主线与节奏、分集提纲四个板块，逐块审核后一键引用 |
| 故事架构 | 核心大纲按「AI 3 个方向 → 爽点公式（选填）→ 创新点 → 冲突主线 → 节奏框架」排列。3 个方向在弹窗里并排对比改写方案、核心设定、冲突主线与创新点，选一个点「确定录入」才写入；冲突主线可逐段改集数与剧情，也可 AI 生成；定好主线后点「生成节奏框架」，付费卡点落在每段结尾、大反转在段中，主线分段显示在折线图下方 |
| 人物设定 | 按人物卡字段生成 / 编辑；关系备注带关系类型（爱人、同学、宿敌…，按剧本描述填写），人物关系图按情感 / 亲属 / 敌对 / 同伴四类着色并在连线上标出类型，可切换为关系表，点人物跳到对应小传 |
| 情节大纲 | 先总览整部剧，再按节奏阶段总结粗纲，最后分批生成集纲；付费卡点集单独审核。总纲可单独生成 / 重新生成（粗纲不动），每一集也可单独生成 / 重新生成集纲（同段其他集不动） |
| 伏笔与叙事线索 | 大纲生成后才能埋伏笔。AI 对照大纲给出伏笔与线索建议，先在弹窗里勾选、改标题和集数，确认后才录入；剧情树 + 线索登记。定稿事件在计划卡片里就地确认：选定稿集与类型，证据须逐字摘自定稿并写明理由，可让 AI 识别填入；「AI 批量确认定稿」一次找出全部推进，勾选后才记入 |
| 逐集剧本 | 见下 |

**逐集剧本**

- **分集蓝图**：写作前的预览设定（本集定位、出场关键人、主角小目标、冲突与转折、承接、末尾钩子、作者微操指导；承接是本集开头要接住什么——上集结尾的钩子，或前几集埋下、本集要响的伏笔，可一键接住还没回收的伏笔；不填时默认接上集结尾的钩子），确认后在本集卡片头点「写作第 N 集」；已有草稿或正文时可「查看本集」。支持批量写作，起止集可选到最后一集（默认一批 5 集；按顺序逐集写，起始集不能越过还没写的集；写作中显示进度、可随时停止，已写出的草稿保留；范围里写过的集另存新版本前会确认）。选中一集后可在表单右上角「重新生成本集蓝图」（只改这一集，作者微操指导与要点保留）
- **草稿箱**：侧栏「逐集剧本」下按集列出所有版本（草稿_v1、v2…）与审核报告。AI 审稿出报告；AI 修稿按最近一份审稿意见逐条改（也可在审核报告里对某一份点「按这份意见修稿」），标注过的行一并改写，没审过稿时按标注与自检修改。新版本记下依据（按审稿 #n）、改了什么和需人工处理的项（如未登记的人物、已回收的伏笔），显示在页头和审核报告里；旧版本只读保留
- **正文章节**：草稿点「定稿」后归入正文章节，自动提炼本集要点回填蓝图，状态库同步更新；正文可继续编辑、一键翻译、中英对照，也可给某一行加标注作改稿提醒
- **剧本编辑器**：稿纸铺满编辑区。点选一行出现 AI 工具条——改写 / 润色 / 扩写 / 续写 / 改成对话，框选部分文字时只改选中的部分；标注在状态库侧栏的「标注」页给选中的行添加（草稿 / 正文页头的「加标注」可直接打开）；操作提示、Markdown 写法与快捷键收在编辑器右上角「编辑说明」里

**剧本状态库（侧栏）**

不再是流程里的一步，而是情节大纲、伏笔与叙事线索、逐集剧本（蓝图 / 草稿 / 正文）页面右侧可展开、收起的侧栏，跟着页面选中的层级显示状态：

- **本集**：截至这一集的状态——阶段与节奏定位（付费卡点、大反转…）、上集钩子与本集钩子、出场人物（首次出场、本集状态变化）、同场关系、场景（新场景 / 哪几集用过）、伏笔（本集需埋 / 需收、进行中、超出计划几集、沉寂提醒，本集定稿后可就地确认定稿事件）；没定稿时附写作前检查。依据依次是定稿 → 草稿（注明不计入全剧）→ 集纲与蓝图推断
- **本阶段**：粗纲、集纲与定稿进度、段内节奏节点、段末人物状态、段内伏笔与场景
- **全剧**：按全部定稿汇总的整体进度、需处理的伏笔、人物最新状态与场景；可打开原来的完整状态库页面（含定稿日志）
- **伏笔超期**：计划的埋设 / 回收集已写过去还没确认时，本集与全剧里都可点「处理」：AI 确认定稿（在定稿里找证据填进表单，由人保存）、还要就改期（改到还没定稿的集，埋设改期时回收同步顺延）、不要了就删除计划

草稿页的侧栏分四个标签：本集蓝图 → 审核报告 → 状态库 → 标注（审稿完成或从目录点开某份报告时切到审核报告）。正文章节页分三个：本集要点（结构化显示，不露 Markdown 符号；剧情节点、角色动态与伏笔推进候选，人物状态看状态库标签）→ 状态库 → 标注。

情节大纲里点总览、某一阶段或某一集，侧栏分别显示全剧 / 本阶段 / 本集；伏笔环节显示写作进度上的当前集；侧栏里可以用下拉直接跳到任意一集 / 一段，或前后翻着临时查看。宽屏（≥1280px）下侧栏展开时页面会给它让出位置，不压住右侧内容。

对标剧仿写模式在新建剧本 / 项目设置里可以直接上传要仿写的剧本，创建后进入「对标剧拆解」即可开始拆解。

### 阶段 3：视频转剧本

只有对标剧视频时，先转成剧本再进入拆解（创作方式选「视频转剧本」）：

1. **获取全集**：粘贴剧集页链接一键下载全集（含付费集），或一次多选上传本地视频（按文件名识别集数）
2. **逐集转写**：自动排队，同时转写 3 集；每集经过下载 → 压缩 → 多模态模型转写，产出带时间码、景别、画面、台词与音效的分镜剧本。队列在页面之外运行，切到别的环节也不会中断；可暂停 / 继续，失败的集单独重试；刷新页面后没跑完的集自动回到排队
3. **合并剧本**：按集数合并，自动修正格式（去掉时间码与景别、接回被镜头切开的台词、半角标点改中文、动作行统一为 △），一键送入「对标剧拆解」
4. **导出**：完整剧本（.txt）、分镜剧本（.csv，含时间码）、全集对白（.txt）

> 演示环境不访问外部链接、不读取视频内容：分集与转写内容取自内置示例剧《The Alpha’s Regret》12 集精简版（`src/services/mock/video.ts`）。接入后端时替换 `services/ai.ts` 里的 `resolveVideoLink` / `transcribeEpisode` / `mergeTranscripts` 即可。

### 质检交付

有定稿正文后即可质检，对已定稿的章节做七项检查：一致性终检、角色一致性（称谓、各阶段是否在场、状态突变 / 停滞）、故事流程（断档、钩子承接、场景单调、阶段情绪递进）、节奏曲线对比、付费点专项、创新点落地、格式合规，按权重汇总成总分。

- **左栏**：质检总结（总分 + 七项分项得分，点分项只看该项问题）与章节目录（每集的问题数）
- **中栏**：定稿正文，有问题的行与字段按严重程度标色
- **右栏**：问题详情与修改建议，点问题定位到对应行；可逐条标记已处理
- **交付**：仍有未处理的严重问题时不能交付；正文在质检后改动过会提示重新质检；交付后可撤回

## 界面版本

页面最底部可以切换「版本一 · 当前方案」与「版本二 · 交互优化」，默认版本一。两个版本共用同一份项目数据，数据结构不变，随时切换对比。

版本二不删功能，围绕核心业务链补上状态与去处：导航显示环节状态与进度、概览「继续工作」直达具体那一集并汇总「待处理」、草稿页按审稿状态推荐主操作、定稿后在正文页接力写下一集、质检「去改正文」带着问题往返、故事架构确认前实时提示还差什么等 12 项。切到版本二后点底部「改动说明」可查看方法与逐项对比，完整说明见 [`docs/版本二-交互优化说明.md`](docs/版本二-交互优化说明.md)。

## 技术栈

React 19 · TypeScript · Vite 8 · Tailwind CSS 4 · React Router 7 · Zustand 5 · lucide-react

## 快速开始

需要 Node.js 20.19+ 或 22.12+（E2E 脚本需要 Node 24+）。

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # 类型检查 + 生产构建，输出到 dist/
npm run preview    # 预览生产构建
npm run typecheck  # 仅类型检查
```

## 目录结构

```
src/
├─ pages/                 # 工作台、我的剧本、新建剧本、项目工作区
│  └─ workspace/
│     ├─ stages/          # 各创作环节

├─ domain/                # 类型、流程环节定义、节奏框架、状态库、校验

├─ store/                 # Zustand 状态（项目持久化、视频转写队列、界面版本、toast）

devtools/annotator/       # 开发期页面标注工具（仅 dev 生效）
scripts/e2e.mjs           # 端到端检查脚本
docs/                     # 设计参考资料、版本二交互优化说明
```

## 开发工具

### 页面标注工具

仅在 `npm run dev` 时注入，不进入生产构建。点击元素进行标注，拖拽可框选区域，`⌥A` 切换标注模式，`Esc` 退出。标注分为修改、新增、删除、Bug、疑问几类，实时写入 `annotations/feedback.json` 和 `feedback.md`（该目录已在 `.gitignore` 中忽略）。

改完的标注可以标记为「已完成」：清单里点「标为完成」，或运行 `node devtools/annotator/done.mjs <编号> "<改了什么>" …`（开着的页面会自动刷新）。已完成的标注不再显示标注点，在清单底部折叠，附上改动说明；没改好可「重新打开」，确认无误后「清除已完成」。`feedback.md` 只详细列出待处理的标注，已完成的在文末各占一行；删掉标注后编号也不回退。

### 端到端检查

用 Chrome DevTools Protocol 驱动无头 Chrome 走一遍主要页面。需要先启动 dev server，并在 macOS 上安装 Google Chrome：

```bash
npm run dev
node scripts/e2e.mjs <输出目录>
```

脚本覆盖立项、故事架构、人物关系、大纲与伏笔、质检交付、设置与存储迁移、状态库侧栏、AI 一键生成全部、正文段落工具栏、审稿 / 修稿兜底，以及版本二的各项交互，共 63 项检查，截图写到输出目录。
