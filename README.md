# 剧本 Agent

面向出海短剧的 AI 剧本创作工作台 Demo：从立项、对标剧拆解、故事架构，到逐集剧本与质检交付，把编剧流程拆成可逐步确认的环节。

> 阶段 1–3（立项、剧本仿写 + 解析、视频转剧本）与质检交付均已上线。AI 能力使用本地模拟（`src/services/ai.ts` + `src/services/mock/`），接口形状与真实大模型调用一致，后续接入后端只需替换 provider。

## 功能

### 阶段 1：立项

- **工作台 / 我的剧本**：剧本卡片、状态（立项中 / 创作中 / 质检中 / 已交付）、搜索与筛选；页头「更新日志」打开 `docs/字段变更日志.md`，按日期列出每轮原型改了哪些字段、哪些页面加了什么，可复制给开发
- **新建剧本**：一整页填完点击创建，只有基本信息、市场与发行两部分；创作方式（原创剧本 / 对标剧仿写 / 视频转剧本）创建后不可更改。题材类型、风格元素、目标受众、核心设定、总集数（20–120 集，新项目默认 20 集）、单集时长（按秒，30–300 秒）、剧本语言立项后都在「故事架构」里填（核心设定可让 AI 给 3 个候选），立项时先用默认值；项目设置里的「故事设定」只读，点「去故事架构修改」过去改；剧本仿写、视频转剧本在对标剧信息里可以填「付费集」（对标剧付费卡点在第几集，多个用「，」隔开、最多 20 个，句号和「第 N 集」写法也认，第一个即首付费；11/5 起，`Benchmark.paywalls`），填了对标剧拆解就按它定一卡和付费卡点集，视频转剧本按它标付费集。
- **项目工作区**：概览（创作进度，项目状态在进度卡右上角点选即保存；故事架构卡、项目设定、动态）、项目设置（「返回」回到来源页，未保存修改离开前拦截）；概览页显示完整页头，进入各环节后页头收成一行（面包屑 + 小封面 + 剧名 + 状态）并吸顶，滚到哪都能换模型，点剧名回概览；点击页头封面可更换封面配色
- **AI 模型**：只分两类，在项目页头「项目设置」前选，改了马上生效、只影响之后的生成——视频解析模型（仅视频转剧本项目，只用于逐集转写，只列能看视频的模型：通义千问 / 豆包 / Gemini，默认通义千问；视频转剧本页的上传框下也能选，和页头是同一个选择）与文本模型（原创、仿写、视频转剧本都一样：拆解、故事架构、人物、大纲、蓝图、正文、审稿、修稿、质检、翻译都用它，可选 DeepSeek、通义千问、豆包、Kimi、GPT、Gemini，默认豆包）。只存改过的那一类，改回默认就不再存。草稿页「重新生成」旁的 ▾ 可临时换模型写这一版，「AI 审稿」旁的 ▾ 临时换模型审这一稿，都不改项目的选择。批量写作开始时锁定当时的文本模型，中途在页头换模型会先说明：本批剩下的集仍用原模型写完（同一批文风一致），新模型从下一次写作生效；也可停止本批立即换，提示里可撤销。草稿页头写明这一版由哪个模型生成（AI 修稿出来的写「修稿」，加入模型选择前写的标「模型未记录」），定稿页「来自草稿」也带模型；审核报告、质检页头与逐集分镜记下审稿 / 质检 / 解析模型。演示版生成内容不随模型变化，只做记录；接入真实接口时在 `services/ai.ts` 按模型分发
- **题材类型 / 风格元素**（11/4 起，替换原来的类型、题材元素、风格基调）：选项取自竞品 StoryPlay，跟着目标市场走——选了日韩用日韩那套（日本、韩国两套清洗后合并，题材类型 26 组 379 个、风格元素 112 个），其余市场用欧美那套（题材类型 18 组 120 个、风格元素 45 个），两种都选了两套都给、分组前标出欧美 / 日韩。题材类型最多选 4 个（原创必选），风格元素分「风格」「元素」两组、最多选 3 个（11/8 按后端接口，原来 3 个 / 5 个）；StoryPlay 的核心设定不用。下拉框左边分组、右边选项，顶上可以搜（也能搜分组名）。存档仍是 `genres`、`tones`；旧项目里的旧标签原样保留，在下拉最前面「不在选项里」一组列出，可以取消。选项由 `scripts/storyplay-clean.mjs` 从 `docs/storyplay-options/` 的原始数据清洗生成到 `src/domain/genreOptions.ts`，清洗规则和逐条记录见 `docs/storyplay-options/clean/清洗记录.md`
- 数据保存在浏览器 localStorage（`zhiying.projects.v1`，带版本迁移），无需后端

### 通用剧本格式

视频解析出来的剧本、AI 写出的正文、编辑器、质检和导出都按同一套格式（`src/domain/scriptFormat.ts`，对齐样稿《池塘通古代我成了西瓜仙人》）：

```
第一集
1-1：日，外，余霍西瓜地
人物：余霍，女搜查官
△ 西瓜地路边，余霍坐在小马扎上，一辆黑色SUV驶来。
△【特写】SUV前车轮沾满西瓜汁与瓜皮。
女搜查官：（严肃）你就是余霍？
余霍os：（咬牙）卖了瓜就能还钱！
母亲（ov）：（哭）小霍！
```

- 集标题写「第一集」；场景标题只存「日 / 夜，内 / 外，地点」，场次号「集-场」按出现顺序自动编；「人物：」行按这一场说话的人和动作里写到的已登记人物自动列出（画外音不算在场）
- 动作行以 △ 开头，镜头提示写在行内：【特写】【快切】【闪回】；台词「角色：（情绪）台词」，内心独白写「角色os：」，画外音写「角色（ov）：」，编辑器里台词前的按钮可切换
- 编辑器里输入「# 天台 夜 外」，离开这一段时改写成「夜，外，天台」；粘贴的「1-1：夜，外，天台」和旧写法「场景：天台 夜 外」都认成场景标题，「第一集」「人物：」行由系统生成，粘贴时跳过
- 导出剧本包：（一）剧本信息（剧名、英文剧名、题材元素、总集数、免费集数、预估总时长）→（二）故事简介（总纲开头【故事简介】那一段）→（三）核心设定（先直接写核心设定那一段话，再列世界观设定、故事背景）→（四）人物小传（名字（男主 / 女主 / 反派）+ 一段小传 + 人物关系 + 外形 / 服装 / 外形参考，次要配角归到「其他配角」）→ 逐集正文（每集开头列「本集人物状态」：每人在哪几场、服化道重点，方便拆资产）
- 导入的对标剧本、视频合并稿也认旧写法（「第1集」「场景：地点 夜 内」「余霍 os：」）

### 阶段 2：剧本仿写 + 解析

每一步页头标明「必做」「必做 · 可一键」或「可跳过」：快速出稿的人跳过能跳的（人工校对、AI 审稿、蓝图细调都可不做），想深度打磨的每一步都有地方展开。

| 环节 | 内容 |
| --- | --- |
| 对标剧拆解 | 导入对标剧本 → AI 拆成三个板块：故事梗概 → 冲突主线 · 内容简介 → 人物设定。故事梗概按编剧给的样例写：核心设定一句话；世界观总分写（世界总览 → 阵营设定 → 主要地点，私设地名写细）；金手指不分类型，最重要的是讲清能力是什么：核心能力每项写是什么、来历、能做到什么（剧里第几集怎么用的）、条件与限制，另写首次出现、表现方式、与主线强相关；核心亮点就是期待值（核心爽点、主线任务（前十集）、情感双线、子类型特征）；故事简介一整段从头讲到尾。冲突主线 · 内容简介的交互类比情节大纲：一行节奏（曲线可收起），左边是按冲突主线分段的目录（吸顶，可展开到每集），右边一次一段——本段梗概（类比阶段总览）+ 段下每集一段集纲（哪部分剧情、通过什么、表现了什么），可上一段 / 下一段或切完整视图，每集可「查看原文」；付费短剧最重要的是第 1 集和付费卡点集（一卡和之后的每个付费卡点）：这几集写集纲 + 五个维度（11/6）——情绪（怎么起伏，不用数字，写成「期待 → 憋屈 → 憋屈到顶 → 回了口气」；哪里压哪里放、属于哪类情绪结果）、节奏（几场、每段快 / 慢 / 卡、集末定格）、信息差（谁知道谁不知道、属于等主角出手 / 替主角急 / 一起猜）、期待感（画了什么饼、怎么加码、兑现程度、集末钩子）、爽点（铺垫 → 出手 → 确认 → 赢回、T1–T3 级别），每项都要具体到某一句台词、某个动作或某个表情（台词用“”，动作、表情用【】引原文）；第 1 集另写开局切入方式（原来的前 3 秒 / 前 30 秒）、全剧最大的底牌和全剧总期待，付费卡点集的卡点写进节奏和期待感。分类和分级沿用 StoryPlay 拆解的五个维度。剧本仿写、视频转剧本一样拆。第 1 集和一卡之间的几集逐场、逐句拆：每句（或一段）写观众此刻的情绪，带来转折的那句标「转折」，就是核心台词，每场串出情绪链，每集把核心台词单独拿出来；其余集只写集纲。每集左边一列栏名（集纲 / 情绪 · 节奏 · 信息差 · 期待感 · 爽点 / 核心台词 / 逐场细拆），从上往下由粗到细，五个维度一块上底色（首集紫、付费卡点橙）；核心台词一栏上面是整集的情绪走向；逐场细拆每一场默认收成一行（场次 · 关键动作 · 几句），点开看逐句（11/4 标注 #70）。人物设定的交互参照人物设定页：左边人物列表，右边这个人的拆解，主角拆简介、身份、金手指、动机（表面追求 / 终极渴望 / 潜意识恐惧），配角拆在这部剧里的作用和定位（性格、背景、缺陷、弧光、事件、代表台词照样拆，存着不显示）；人物的「关系」里列出他的关系，全剧关系网有关系图（点人物切到他）和关系表。拆解结果只读（11/8）：三个板块都不能改、不能增删人物 / 关系 / 场 / 句，要改就「重新拆解」；不逐块审核，拆完就能在页面底部条里「一键引用」（底部条也能点板块名跳过去），点了直接进故事架构，不再弹窗换算节奏框架（本项目集数在故事架构里定，节奏框架在那里生成冲突主线时按分段换算，11/8）；视频转剧本送来的剧本进来直接开始拆（11/4 标注 #72–#79），粘贴 / 上传剧本点「导入并切分」后、新建剧本时就上传了剧本的进来，也都直接开始拆，不用点「开始拆解」（11/8）。示例剧本的故事梗概、冲突主线、主角和配角的拆解、首集和付费卡点集的集纲与五个维度、一卡前的逐句细拆是按样例手写的参考稿（`src/services/mock/sampleAnalysis.ts`），别的剧本按关键词规则粗拆，只保证格式 |
| 故事架构 | 从核心设定往下一项项推出整部剧，不分层，所有项放在一张「各项设定」里，每项是左侧带序号的节点（有内容实心、空着空心），按编剧的顺序：原创 核心设定 → 世界观设定 → 金手指 / 核心卖点 → 故事背景 → 核心亮点 → 主角人设 → 冲突主线（节奏框架在冲突主线表格下面）→ 全局写作要求（参考作品、整体框架、主要势力 11/4 删掉，生成不再读，字段和旧数据留着；创新点原创不要）；核心亮点（11/4 标注 #71）写期待值（核心爽点、观众等着看哪几场、情感期待）和情绪（主打情绪、情绪走向），全局写作要求按它写每集要给到的情绪，全剧总览写了它就写成【核心亮点】；仿写没有改写方案，也没有改写想法（11/5 标注 #87 删掉，编剧的想法直接写进核心设定），主角人设和冲突主线之间多一项创新点（对标剧怎么做 → 我们怎么做，设定写完后和对标剧比），其余相同。顺序在 `src/domain/basis.ts` 的 `ARCH_ORDER`。基本信息只有题材类型、风格元素、目标受众、总集数、单集时长、剧本语言（目标受众必选，新项目先空着、确认故事架构前要选；故事结构、叙事视角、爽点公式、沉寂提醒阈值 11/4 删掉，生成不再读）。节奏框架的付费卡点集（第一个即首付费）、大反转集、结局高潮起始集直接放在冲突主线表格下面，可直接改；曲线默认收起，展开后可在曲线上点选；曲线上的目标情绪强度只是示意（还没有打分依据）；冲突主线生成时顺带按分段生成节奏框架。各项里只有核心设定必填，其余都可以空着（`ARCH_REQUIRED`）。状态、还差什么、「AI 生成」和「确认故事架构」在页面底部的悬浮条上，滚到哪都在；「AI 生成「X」」每次只生成下一个空着的项，生成完停下来等编剧看，看过点「继续生成「下一项」」再往下；每项只读编剧写的和排在前面的项，已有内容不覆盖（冲突主线只补空着的段）；「确认故事架构」后整页只读，「修改故事架构」后重新确认。每项名字旁 ⓘ 写明依据的三段式（必须遵守 / 重点参考 / 不违背即可）；上游改过不自动重写（各项下面不再显示「依据说明」和「依据已改」两行，标记和依据指纹仍记在数据里）。世界观总分写（世界总览 → 阵营设定 → 主要地点），金手指不分类型、写核心能力和表现方式，故事背景写成一段故事简介；逐项 AI 生成和 AI 方向卡都按这个写法出（`src/services/mock/setting.ts`），后面的项新旧写法都能读。核心设定框下面是「AI 框架方向」（11/5 标注 #86，原名「AI 给出 3 个方向」），3 个方向各列出核心设定、世界观、金手指、故事背景，选中后一起录入（「AI 评估可行性」11/4 去掉）。主角人设可写成人物卡，人物设定 AI 生成时按卡拆到小传。仿写的冲突主线分两个标签：先是「对标剧（拆解）」（只读），再是「修改冲突主线」（编剧定段落、每段集数和剧情，可增删段），两张表表头一样（段落 / 集数 / 剧情）；不用选每段对应对标剧哪一段，系统按默认规则对（段数相同一一对，不同按段名和位置配，新加的段不对位）；节奏框架、对标剧虚线都按分段对位换算（`src/domain/align.ts`） |
| 人物设定 | 按人物卡字段生成 / 编辑；小传每一项旁都有 AI 生成 → AI 润色，名字旁的 ⓘ 标出这一项按什么生成；定位可自定义（如「女主闺蜜」），另选按哪一类检查；已有人物时「重新生成」只补不换：已有的人物和填过的内容都保留，只补缺的角色、空着的项和还没有的关系；关系备注带关系类型（爱人、同学、宿敌…，按剧本描述填写），人物关系图按情感 / 亲属 / 敌对 / 同伴四类着色并在连线上标出类型，可切换为关系表，点人物跳到对应小传 |
| 情节大纲 | 按「总纲 → 阶段总览 → 集纲」的顺序生成：有总纲才能生成各阶段总览，本段有阶段总览才能生成本段集纲（段落卡片头「生成阶段总览」在「一键集纲」前面）；「AI 一键生成全部」补齐没生成的部分，全部生成后变成「重新全部生成」，确认后整份重写。付费卡点集单独审核，点「付费卡点待审核」依次跳到待审核的集。总纲、每段阶段总览、每一集集纲都可单独生成 / 重新生成，不动其他部分。阶段总览开头先写这一段的剧情概况（按集串成一段话），再写「段名（集数）：冲突主线」、节点、金手指；集纲写成一段：发生了什么 → 主角怎么应对、为什么 → 推进到哪（写作开场只写第一句）。大纲检查（钩子轮换、付费卡点与大反转位置）在状态库侧栏的「检查」页，列出的集号点一下跳到那一集 |
| 逐集剧本 | 见下 |

**逐集剧本**

- **逐集蓝图**（11/5 标注 #89 从「分集蓝图」改名）：每一集都先列出来，没存过的按情节大纲的集纲和人物设定预填（标题、冲突、钩子照集纲，出场关键人是主角加集纲里提到的人物，人物本集状态先按人物设定的服装列；`prefillBlueprint` 在 `src/pages/workspace/script/ops.ts`），编剧改了或写作这一集时才存进数据，没存的跟着情节大纲和人物设定变；「恢复预填 / 全部恢复预填」把存过的改回预填，本集要点保留；没有集纲的集标「待集纲」。本集卡片头的「去写第 N 集」不走 AI（11/5 标注 #93；#91 时放在写作按钮的 ▾ 里）：新建一版按本集蓝图列好开头承接和末尾钩子的草稿，直接在编辑器里写，草稿标「自己写」（`EpisodeDraft.manual`）；要 AI 写用批量写作，或在草稿页「重新生成」。单集流程步骤条 11/5 标注 #90 全局删掉，只留左侧列表的进度点。写作前的预览设定（出场关键人、冲突与转折、承接、末尾钩子、人物本集状态；本集定位、主角小目标、作者微操指导 11/4 删掉，定位仍按节奏框架标在左侧集列表里；人物本集状态登记每人从哪一场进来、这一场的服化道重点，状态库人物栏和导出都用这一份；承接是本集开头要接住什么——上集结尾的钩子；不填时默认接上集结尾的钩子），确认后在本集卡片头点「去写第 N 集」；已有草稿或正文时可「查看本集」。支持批量写作，起止集直接输入集数，可写到最后一集（默认一批 5 集；按顺序逐集写，起始集不能越过还没写的集；批量写作在后台跑，离开逐集蓝图页也接着写，页头显示进度、可随时停止，已写出的草稿保留；范围里写过的集另存新版本前会确认）。选中一集后可在表单右上角「重新生成本集蓝图」（只改这一集，本集要点保留）。写作前检查在状态库侧栏的「检查」页，本集卡片头写明有几条要留意。「+」补上缺蓝图的集；全部集都有蓝图时，确认后加一集（总集数加一，节奏框架随之调整）
- **草稿箱**：侧栏「逐集剧本」下按集列出所有版本（草稿_v1、v2…）与审核报告。页头按 重新生成 → AI 润色 → AI 审稿 → AI 修稿 → 定稿 排列；AI 润色整集去 AI 味、改顺句子，先看改前改后再采用，采用后可撤销；审稿可以跳过，没审稿也能直接定稿。AI 审稿出报告；AI 修稿按最近一份审稿意见逐条改（也可在审核报告里对某一份点「按这份意见修稿」），标注过的行一并改写，没审过稿时按标注与自检修改。新版本记下依据（按审稿 #n）、改了什么和需人工处理的项（如未登记的人物），显示在页头和审核报告里；旧版本只读保留
- **审稿依据**：AI 写作与 AI 审稿对照同一份清单——核心设定（全局写作要求里明确不许出现的内容）、人物设定（人物登记、主角戏份、寡言的人不说长句）、状态库（人物状态、道具归属）、集纲（本集事件写进正文）、蓝图（开场承接、出场人物）、格式与篇幅、文风。每条审稿意见写明依据哪一项、依据原文与正文原句（点原句定位到那一行）；说不出依据的只算建议，不拦定稿。写作时按这几项写，草稿侧栏「本集蓝图」下列出这一版的「写作依据」
- **复审与收敛**：AI 修稿出来的版本再审稿是「复审」，只看上一轮意见改没改掉、改过的段落有没有新问题，不再从头挑；报告里标出已改掉 / 仍在 / 新发现，需要时可点「全量重审」。一条意见两轮没改掉、或改好后又出现，标为「AI 改不动，需人工」，之后修稿不再交给 AI；修稿仍最多 3 轮。编剧可对任一意见「保留不改」（严重问题要写理由，建议一键保留，可撤销），保留的意见之后的审稿不再提。只有严重问题拦定稿：定稿时还有没解决的严重问题，要么回去改，要么逐条写明理由保留
- **正文章节**：草稿点「定稿」后归入正文章节，自动提炼本集要点回填蓝图，状态库同步更新；正文可继续编辑、一键翻译、中英对照，也可给某一行加标注作改稿提醒
- **一键定稿**：逐集蓝图页头「一键定稿」列出每集最新一版还没定稿的草稿，审过稿、没有严重问题、不替换已有正文的默认勾上；未审稿、审稿后改过、会替换正文的要手动勾；最近一次审稿还有严重问题的不能选，可点「去处理」。确认后按集号依次定稿
- **剧本编辑器**：稿纸铺满编辑区。点选一行出现 AI 工具条——改写 / 润色 / 扩写 / 续写，框选部分文字时只改选中的部分；标注在状态库侧栏的「标注」页给选中的行添加（草稿 / 正文页头的「加标注」可直接打开）；操作提示、Markdown 写法与快捷键收在编辑器右上角「编辑说明」里

**剧本状态库（侧栏）**

不再是流程里的一步，而是情节大纲、逐集剧本（蓝图 / 草稿 / 正文）页面右侧可展开、收起的侧栏，跟着页面选中的层级显示状态（情节大纲与逐集蓝图页另有「检查」页，放大纲检查 / 写作前检查）：

- **本集**：截至这一集的状态——阶段与节奏定位（付费卡点、大反转…）、上集钩子与本集钩子、人物（一张紧凑的表：名称、定位、「首次出场」「妆造变 N 次」，下面一场一行列进场的场景和服化道重点，没换装的几场合成一格）、同场关系、场景（新场景 / 哪几集用过）。依据依次是定稿 → 草稿（注明不计入全剧）→ 集纲与蓝图推断
- **本阶段**：阶段总览、集纲与定稿进度、段内节奏节点、段末人物状态、段内场景
- **全剧**：按全部定稿汇总的整体进度、人物最新状态与场景；可打开原来的完整状态库页面（含定稿日志）

草稿页的侧栏分四个标签：本集蓝图 → 审核报告 → 状态库 → 标注（审稿完成或从目录点开某份报告时切到审核报告）。正文章节页分三个：本集要点（结构化显示，不露 Markdown 符号；剧情节点、角色动态，人物状态看状态库标签）→ 状态库 → 标注。

情节大纲里点总览、某一阶段或某一集，侧栏分别显示全剧 / 本阶段 / 本集；侧栏里可以输入集数直接跳到任意一集、用下拉选任意一段，或前后翻着临时查看。宽屏（≥1280px）下侧栏展开时页面会给它让出位置，不压住右侧内容。

对标剧仿写模式在新建剧本 / 项目设置里可以直接上传要仿写的剧本，创建后进入「对标剧拆解」就直接开始拆解。

### 阶段 3：视频转剧本

只有对标剧视频时，先转成剧本再进入拆解（创作方式选「视频转剧本」）：

1. **获取全集**：粘贴剧集页链接一键下载全集（含付费集），或一次多选上传本地视频（按文件名识别集数）
2. **逐集转写**：自动排队，一集一集依次转写（转完一集再转下一集）；每集经过下载 → 压缩 → 多模态模型转写，产出带时间码、景别、画面、台词与音效的分镜剧本。队列在页面之外运行，切到别的环节也不会中断；可暂停 / 继续，失败的集单独重试；刷新页面后没跑完的集自动回到排队。没按模板输出的集（台词写进了画面描述）在转写表里标「没按模板」
3. **合并剧本**：按集数合并，按规则自动整理成通用剧本格式（集标题「第一集」、场景标题编成「1-1：日，外，地点」并补「人物：」行、去掉时间码、特写镜头标【特写】其余景别不写、接回被镜头切开的台词、半角标点改中文、动作行统一为 △、内心独白 / 画外音标 os / （ov）），不用模型；合并后卡片头只写合并时间和全剧字数，自动修正了哪几类写在左边
4. **人工校对**（可跳过）：后台按模板约束转写输出，格式不会错，所以不做 AI 校对；剧本内容对不对只能对照视频看。选一集，左边视频、右边按通用剧本格式排出这一集的转写稿（场次标题 / 人物 / △ 动作 / 台词），每行记着对应镜头的时间：点一行或场次标题视频跳到那一刻，播放时右边跟着走；听错的台词点 ✎ 改，点「确认」（或 Enter）才保存，失焦不保存；卡片头显示改过几集，转写表标「校对改过」。合并后又改过转写稿的，提示「重新合并」
5. **送入拆解**：一键送入「对标剧拆解」，之后的拆解、创作、审稿、质检都用文本模型
6. **导出**：完整剧本（.txt）、分镜剧本（.csv，含时间码）、全集对白（.txt）

> 演示环境不访问外部链接、不读取视频内容：分集与转写内容取自内置示例剧《The Alpha’s Regret》12 集精简版（`src/services/mock/video.ts`）。接入后端时替换 `services/ai.ts` 里的 `resolveVideoLink` / `transcribeEpisode` / `mergeTranscripts` 即可。人工校对页选了本地视频文件就播真实视频，链接下载的集用模拟播放（按时间轴走，画面处显示这一镜头的画面描述和字幕）。

### 质检交付

有定稿正文后即可质检，对已定稿的章节做自动检查：一致性终检、角色一致性（称谓、各阶段是否在场、状态突变 / 停滞）、故事流程（断档、钩子承接、场景单调、阶段情绪递进）、节奏曲线对比、付费点专项、格式合规，仿写（剧本仿写、视频仿写）另查创新点落地，按权重汇总成总分。原创没有创新点，六项（创新点落地的 10% 分给一致性终检和付费点专项），左侧目录的「全剧」一栏列跨集问题；仿写七项（`src/domain/pipeline.ts` 的 `qaChecks`）。

- **质检总结**：横排在交付操作下方，总分 + 各项分项得分；下面列出全部问题，点分项或严重 / 建议 / 提示筛选，可清除筛选
- **左栏**：章节目录（每集的问题数）
- **中栏**：定稿正文，有问题的行与字段按严重程度标色
- **右栏**：所选这一集（或全剧）的问题与修改建议，点问题定位到对应行；可逐条标记已处理
- **AI 修稿**：正文问题的卡片都有「AI 修稿」，只改问题涉及的行；补写的内容只取蓝图、集纲、状态库和已登记人物，新增未登记人物、已退场人物开口、对标剧人名都会撤回并列给编剧手改。先预览改动与「已对照原有设定」，确认后才写进定稿，问题记为「AI 已修」；重新质检仍检出会重新列出
- **交付**：仍有未处理的严重问题时不能交付；正文在质检后改动过会提示重新质检；交付后可撤回
